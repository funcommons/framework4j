# **API 响应结构与错误码规范 v1.3 (完整版)**

## **1\. 概述**

本规范旨在定义系统 API 接口的统一响应格式（Response Structure）与错误码（Error Code）标准。  
核心目标：

* **精简高效**：移除冗余字段，降低网络传输开销。  
* **类型安全**：状态码使用数字类型，便于客户端高效判断。  
* **可观测性**：通过 trace\_id 贯穿全链路追踪。  
* **健壮性**：防止 null 指针异常，解决大整数（BigInt）精度丢失问题。

## **2\. 基础响应结构 (Standard Envelope)**

所有 HTTP API 响应（包括 200 OK 和非 200 的业务异常）都 **必须** 遵循以下 JSON 结构：

{  
  "code": 0,  
  "message": "操作成功",  
  "data": { ... },  
  "error": { ... },  
  "trace\_id": "a1b2c3d4e5f6g7h8"  
}

### **2.1 字段定义**

| 字段名 | 类型 | 必返 | 描述 | 规范说明 |
| :---- | :---- | :---- | :---- | :---- |
| **code** | Integer | 是 | 业务状态码。 | **核心判断依据**。0 表示成功，非 0 表示失败。 |
| **message** | String | 是 | 用户提示信息。 | 成功时为 "OK" 或 "操作成功"；失败时为具体的错误描述（如 "库存不足"）。 |
| **data** | Any | 是 | 业务数据载荷。 | 成功时返回对象、数组或 null；**失败时必须返回 null**。 |
| **error** | Any | 否 | 错误详细信息。 | **仅在失败时可选返回**。用于携带表单验证错误详情、开发环境堆栈信息等。 |
| **trace\_id** | String | 是 | 全链路追踪 ID。 | **核心字段**。必须与透传给数据库 SQL 注释中的 traceid 保持一致，用于排查问题。 |

## **3\. 错误码规范 (Error Codes)**

错误码采用 **5 位数字** 格式：ABCCC。

* A: **错误来源级** (1: 系统/通用, 2: 业务A, 3: 业务B...)  
* B: **模块/类别级** (0: 系统, 1: 请求, 2: 认证, 3: 权限, 4: 资源, 5: 流量, 6: 上传)  
* CCC: **具体错误** (001-999)

### **3.1 系统与基础设施类 (10xxx)**

此类错误通常是无需用户干预的服务器端问题。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10001** | 500 | 系统繁忙，请稍后再试 | **兜底错误**。未捕获的异常 (NPE, 数据库连接失败, 索引越界)。 |
| **10002** | 503 | 服务暂停维护 | 系统维护模式开启，拒绝所有请求。 |
| **10003** | 504 | 服务调用超时 | 网关超时、RPC 调用下游服务超时。 |
| **10004** | 502 | 第三方服务异常 | 调用外部 API（如微信支付、短信网关）失败。 |
| **10005** | 500 | 中间件服务异常 | Redis 连接失败、MQ 投递失败等。 |

### **3.2 请求与参数校验类 (101xxx)**

此类错误通常由客户端传参不当引起，需要前端开发人员介入。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10100** | 400 | 请求参数错误 | **通用参数错误**。通常配合 error 字段展示具体字段校验信息。 |
| **10101** | 400 | 必填参数缺失 | @NotNull, @NotBlank 校验失败。 |
| **10102** | 400 | 参数格式错误 | 邮箱、手机号正则校验失败；日期格式解析失败。 |
| **10103** | 400 | 请求体格式错误 | JSON 解析失败 (Malformed JSON)；XML 解析失败。 |
| **10104** | 405 | 请求方法不支持 | HTTP Method Mismatch (如 GET 请求用了 POST)。 |
| **10105** | 415 | 媒体类型不支持 | Content-Type 错误 (如接口要求 application/json 但传了 form-data)。 |
| **10106** | 400 | 业务规则校验失败 | 如：结束时间不能早于开始时间；金额不能为负数。 |

### **3.3 认证与账号类 (102xxx)**

此类错误与 AuthN (Authentication) 相关，主要解决“你是谁”的问题。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10200** | 401 | 用户未登录 | Token 缺失、Token 格式错误。 |
| **10201** | 401 | 登录凭证已过期 | Token 过期 (Expired)，前端需引导刷新 Token 或重新登录。 |
| **10202** | 401 | 登录凭证无效 | Token 签名校验失败、Token 被伪造。 |
| **10203** | 401 | 账号密码错误 | 登录接口专用。 |
| **10204** | 401 | 账号已被冻结 | 账号状态异常 (Disabled/Locked)。 |
| **10205** | 401 | 账号在异地登录 | 被踢下线 (Kickout)。 |
| **10206** | 401 | 验证码错误 | 图形验证码或短信验证码校验失败。 |
| **10207** | 401 | 令牌格式错误 | JWT 三段式破坏、Base64 解码失败。 |
| **10208** | 401 | 令牌已注销 | access token jti 在撤销集合中（主动登出/踢下线/family 撤销）。 |
| **10210** | 401 | 刷新令牌已过期 | refresh TTL 到期 / family hash 不存在。 |
| **10211** | 401 | 刷新令牌无效或已使用 | refresh 类型错 / 签名错 / family 毒丸触发 / 旧 refresh 重用。 |
| **10212** | 401 | 刷新令牌轮转次数超限 | family generation 达到 maxRotations 上限。 |

### **3.4 权限与授权类 (103xxx)**

此类错误与 AuthZ (Authorization) 相关，主要解决“你能不能做”的问题。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10300** | 403 | 无权限访问 | **通用鉴权失败**。缺少所需角色或权限点。 |
| **10301** | 403 | 数据权限不足 | 有功能权限，但无权操作该行数据 (Row-level Security)。 |
| **10302** | 403 | 签名验证失败 | 接口签名 (Signature) 校验不通过，防篡改校验失败。 |
| **10303** | 403 | IP 限制访问 | IP 白名单拦截。 |

### **3.5 资源与数据类 (104xxx)**

此类错误与具体的业务资源状态相关。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10400** | 404 | 请求资源不存在 | **通用 404**。ID 查询为空，或 URL 路径错误。 |
| **10401** | 409 | 数据已存在 | 唯一性约束冲突 (Duplicate Key)。如用户名已注册、编码重复。 |
| **10402** | 409 | 数据状态冲突 | 状态机流转失败。如：订单已取消，不能发货。 |
| **10403** | 423 | 数据被锁定 | 悲观锁/分布式锁获取失败，资源正忙。 |
| **10404** | 400 | 数据完整性约束失败 | 级联删除失败，或外键约束报错。 |

### **3.6 流量控制与文件上传类 (105xxx)**

此类错误用于系统自我保护与文件上传校验。v1.7 起文件上传码从原 106xx 段迁入本段。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10500** | 429 | 请求过于频繁 | **通用限流**。触发 QPS 限制。 |
| **10501** | 429 | 请勿重复提交 | 幂等性校验失败 (Idempotency)。 |
| **10502** | 503 | 服务降级 | 熔断器开启 (Circuit Breaker Open)。 |
| **10503** | 400 | 文件上传失败 | IO 异常或存储服务异常（原 10600）。 |
| **10504** | 400 | 文件类型不支持 | 后缀名或 Magic Number 校验失败（原 10601）。 |
| **10505** | 413 | 文件体积过大 | 应用层主动判定超限（原 10602）。 |
| **10506** | 400 | 文件内容为空 | 上传了空文件（原 10603）。 |

### **3.7 业务自定义类 (106xxx)**

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **106xx** | 200 | 业务自定义 | 通用错误码无法精确表达的业务规则（如余额不足、风控）。各业务线按需登记认领。 |

### **3.8 业务混合结果类 (107xxx)**

适用于批量操作中「部分成功 + 部分失败」的场景。

| 错误码 | HTTP Status | 描述 (Message) | 适用场景 |
| :---- | :---- | :---- | :---- |
| **10700** | 200 | 部分成功 | 同步批量操作 N 条中 M 条失败（M < N，N ≤ 100）。`data` 非 null，含 `failures` 列表。 |

## **4\. 示例**

### **4.1 成功响应**

{  
  "code": 0,  
  "message": "ok",  
  "data": {  
    "id": "892310293123123",  
    "name": "Admin User"  
  },  
  "trace\_id": "c0a8010116983728001"  
}

### **4.2 失败响应 (带详细错误)**

{  
  "code": 10100,  
  "message": "请求参数错误",  
  "data": null,  
  "error": \[  
    {  
      "field": "email",  
      "message": "邮箱格式不正确",  
      "value": "invalid-email"  
    },  
    {  
      "field": "password",  
      "message": "密码长度不能少于6位"  
    }  
  \],  
  "trace\_id": "c0a8010116983728002"  
}

## **6\. JSON Schema**

本节提供用于自动化验证的 Schema，分为成功与失败两种场景。

### **6.1 成功响应 Schema (code=0)**

成功时，code 必须为 0，data 可以是任何数据（包括 null），error 字段应不存在或为 null。

{  
  "$schema": "\[http://json-schema.org/draft-07/schema\#\](http://json-schema.org/draft-07/schema\#)",  
  "title": "Success Response Schema",  
  "type": "object",  
  "required": \[  
    "code",  
    "message",  
    "data",  
    "trace\_id"  
  \],  
  "properties": {  
    "code": {  
      "const": 0,  
      "description": "成功时状态码固定为 0"  
    },  
    "message": {  
      "type": "string",  
      "examples": \["操作成功", "OK"\]  
    },  
    "data": {  
      "description": "业务数据载荷"  
    },  
    "error": {  
      "type": "null",  
      "description": "成功时 error 字段应为空"  
    },  
    "trace\_id": {  
      "type": "string",  
      "description": "全链路追踪 ID"  
    }  
  }  
}

### **6.2 失败响应 Schema (code\!=0)**

失败时，code 为非 0 整数，data 必须为 null，error 字段可选返回详细信息。

{  
  "$schema": "\[http://json-schema.org/draft-07/schema\#\](http://json-schema.org/draft-07/schema\#)",  
  "title": "Failure Response Schema",  
  "type": "object",  
  "required": \[  
    "code",  
    "message",  
    "data",  
    "trace\_id"  
  \],  
  "properties": {  
    "code": {  
      "type": "integer",  
      "not": { "const": 0 },  
      "description": "失败时状态码为非 0 整数"  
    },  
    "message": {  
      "type": "string",  
      "description": "错误提示信息"  
    },  
    "data": {  
      "const": null,  
      "description": "失败时 data 必须为 null"  
    },  
    "error": {  
      "description": "错误详情，仅在需要时返回",  
      "anyOf": \[  
        { "type": "object" },  
        { "type": "array" },  
        { "type": "string" },  
        { "type": "null" }  
      \]  
    },  
    "trace\_id": {  
      "type": "string",  
      "description": "全链路追踪 ID"  
    }  
  }  
}
