# **ldx2t-commons 分布式 ID SDK 产品文档**

## **1\. 产品概述**

**ID SDK** 是一款专为云原生与容器化环境（Kubernetes/Docker）设计的高性能分布式唯一 ID 生成组件。

它基于经典的 **Twitter Snowflake（雪花算法）** 进行深度优化，解决了传统雪花算法在容器漂移场景下 WorkerID（机器标识）冲突的痛点，并提供了符合互联网业务需求的 **OpenID 混淆** 与 **ID 反解析** 能力。

## **2\. 核心痛点与解决方案**

| 痛点场景 | 传统方案问题 | ID SDK 解决方案 |
| :---- | :---- | :---- |
| **K8s 容器漂移** | Pod 重启后 IP 变化，依赖 IP 计算 WorkerID 会导致 ID 冲突或无限增长。 | **Redis 租约 \+ 心跳机制**：自动分配、回收空闲 WorkerID，支持无状态扩缩容。 |
| **前端精度丢失** | JS Number 无法精确表示 19 位 Long ID，导致后几位变 0。 | **OpenID 方案**：后端自动将 ID 混淆为带业务前缀的字符串（如 ORD\_x9k2...），前端透传字符串，零精度风险。 |
| **业务数据泄露** | ID 自增或连续，竞对可通过爬虫推算业务单量。 | **加盐混淆**：ID 转换为无序字符串，隐藏真实业务量。 |
| **故障排查困难** | 拿到 ID 后不知道是哪天生成的，必须查数据库。 | **ID 反解析工具**：无需查库，通过算法直接从 ID 还原精确到毫秒的生成时间。 |

## **3\. 核心功能特性**

### **3.1 高性能 ID 生成**

* **算法**: 标准雪花算法 (Snowflake)。  
* **类型**: Long (64位)。  
* **性能**: 本地计算，无网络 I/O，单机支持 400w+ QPS。  
* **特性**: 全局唯一，趋势递增（按时间有序）。

### **3.2 容器化友好 (K8s Ready)**

* **自动注册**: 节点启动时自动向 Redis 申请 WorkerID (0-1023)。  
* **自动续期**: 内置守护线程每 6 小时维持一次租约。  
* **自动回收**: 节点崩溃或缩容后，WorkerID 在 24 小时后自动释放给新节点使用。

### **3.3 业务安全与混淆 (OpenID)**

* **双向转换**: 支持 Long ID \<-\> String OpenID 互转。  
* **业务前缀**: 支持自动追加/剥离业务前缀（如 USER\_）。  
* **安全加盐**: 内置硬编码盐值，防止算法被反推。

## **4\. 适用场景**

* **核心业务主键**: 用户 ID、订单 ID、商品 ID、优惠券 ID。  
* **高并发流水号**: 支付流水、日志链路 ID。  
* **对外展示 ID**: 需要在 URL 或 App 端展示给用户的 ID。

## **5\. 局限性说明**

* **非严格递增**: ID 总体随时间增加，但不是严格的 1, 2, 3 顺序（不适用于发票号、合同号等财务严格场景）。  
* **依赖 Redis**: 必须依赖 Redis 进行 WorkerID 的协调管理。
