版本历史 ​

单源：本页由仓库 README.md「版本历史」镜像——变更请改 README 后同步此处。 各版本完整 release notes 见 GitHub Releases。

版本关键变更
v1.10.0⚠️ 安全默认变更 + datasource 共存治理 — Issue #28/#29:
① [datasource] 缺省 filters 去 wall（升级必读）:datasources.&lt;name&gt;.druid.filters 缺省 stat,wall,slf4j → stat,slf4j——wall 的 comment not allow 策略拦截注释 SQL,与同仓 sql-tracing 的 /*traceid=...*/ 前缀互斥（同仓两件互相废掉对方核心功能）,也拦掉 Flyway 带注释迁移脚本。依赖默认 wall 防注入的消费方升级后须显式选配 stat,wall,slf4j（并自行处理注释冲突,如 wall commentAllow 豁免 /*traceid= 前缀）
② [#29-1] 装配排序治理:MultiDataSourceAutoConfiguration 显式 @AutoConfigureBefore(DataSourceAutoConfiguration/DruidDataSourceAutoConfigure)——框架 datasources 存在时五件套先注册,Boot/Druid 装配让位,v1.9 及之前消费方被迫的双 exclude 不再必须
③ [#29-2] 功能修复 + 契约文档化:框架 MybatisPlusInterceptor（方案 C 分页/防全表更新/乐观锁）此前从未 wire 进框架 SqlSessionFactory——plugins 属性缺失,拦截器一直是"惰性 bean"从未生效;v1.10 按类型注入,用户自定义同名 bean 自动接管。MP 定制迁移清单（GlobalConfig/TypeHandler → config-location 或自建工厂）见 datasource README §3.1
④ [#29-3] 两个 BeanPostProcessor @Bean 方法静态化,消除 BPPChecker WARN
⑤ 防回归:MultiDataSourceAutoConfigurationOrderingTest（排序让位/拦截器 wiring/用户 bean 接管/BPP 静态化 5 例）+ DruidFiltersDefaultTest（缺省无 wall）
⑥ 顺带:在线文档站上线（funcommons.github.io/framework4j,VitePress + Actions,内容源勘误同步）
⑦ [datetime] 序列化 wire 契约修复（issue #30）:DynamicTimeFilter 默认态/注解 ISO 态从变长 toString()（秒为 0 时省略秒段,同一字段 wire 形态随数据漂移）改定长 yyyy-MM-dd'T'HH:mm:ssXXX;本地格式分支此前按值自带 offset 排墙钟（javadoc 宣称 GMT+8 但零换算,UTC 值错 8 小时且格式正常极隐蔽）——格式化前 atZoneSameInstant 换算,新键 framework4j.datetime.local-zone（缺省 Asia/Shanghai,非法值启动 fail-fast）。顺带勘误 datetime README 虚构键（default-zone/use-iso-format/@TimeFormat 均不存在,实际为 @LocalTimeFormat;模块也无毫秒时间戳模式）
v1.9.0⚠️ 依赖面收紧 — Issue #27:SDK 各模块不再向消费方强加 servlet 容器面。① [idempotency] spring-boot-starter-web 改 &lt;optional&gt;true</optional>——此前是全仓库唯一 compile 非 optional 的 web starter（framework4j-all 消费方 tomcat-embed-core 泄漏的实际来源,WebFlux 反应式网关被翻转成 Tomcat 工厂 → WSS 握手 ClassCastException）;配套 IdempotencyAutoConfiguration 补 @ConditionalOnClass(WebMvcConfigurer) + @ConditionalOnWebApplication(SERVLET)——非 servlet 环境整体静默跳过（对齐 signature/rate-limit 口径）,与 #26 显式启用同理
② [cache] 删除遗留依赖 framework4j-web + jakarta.servlet-api（主代码与测试零引用）
③ [signature/rate-limit] jakarta.servlet-api compile→provided（拦截器主代码在用,容器提供,不外泄;对齐 accesstoken 口径）
④ 防回归:DependencyLeakGuardTest（compat-test）解析 21 个模块 pom 锁定「web starter 必须 optional、servlet-api 不得裸 compile」结构契约;IdempotencyServletFreeTest 锁定无 servlet 环境装配跳过。升级注意:若消费方此前靠 idempotency/cache 传递获得 spring-boot-starter-web,请显式声明自己的 web 依赖
v1.8.0⚠️ 破坏性变更 — Issue #26/#25/#23 补全 + 统一 AI skill:
① [id] 显式启用（升级必读）:framework4j.id.enabled / framework4j.openid.enabled 改 matchIfMissing=false——classpath 即激活的历史语义废除,升级后未显式配置=true 的应用模块静默失活（子开关 mybatis.enabled 等保持缺省跟随）。配套 fail-soft:redis 策略 WorkerID 申请失败自动降级 IP Hash（framework4j.id.worker.fallback-to-ip,默认 true;槽位耗尽仍抛错不降级防碰撞）,无 Redis 的测试/CI 不再启动即炸。新异常 WorkerIdRedisException(IllegalStateException 子类,向后兼容)。配置键勘误:文档历史键 worker-id-strategy/ip-hash 均不存在,真键 framework4j.id.worker.strategy(redis|ip);framework4j.id.epoch/redis.lease-seconds/redis.renew-interval 为虚构键已从文档清除
② [web/tracelog] trace_id 契约三缺口（issue #25,兑现 mc-monitor 契约）:traceIdMdcFilter 采纳合法入站 X-Trace-Id（16~64 位白名单 sanitize,不再另行生成断链）;chain 前回显响应头（异常/提前提交路径也带）;MDC key 可配 framework4j.api.trace.mdc-key（默认 traceId 零破坏,tracelog 采集三处硬编码同步）
③ [accesstoken] refresh 链路 claims 嵌入（issue #23 补全）:新键 framework4j.access-token.embed-claims（默认 false）——此前签发嵌入后首次轮转 payload claims 即丢
④ 统一 AI skill（第三方 AI 工具即拷即用）:15 个模块 skill 收敛为 skills/framework4j/ 单源——SKILL.md 入口（~120 行,架包坐标+模块路由表+跨模块硬规范）+ references/ 17 个精华文档按需加载;旧 skills/fwk4j-<module>/ 目录删除
